# 04 · 批量导入漫画：方案设计与操作手册

> 目标：把 PC 上 `manga/` 里几百话漫画，用最少的手工操作灌进平板，而不是在系统文件选择器里一话一话点。

> **状态：方案 A（目录导入）已实施并在 vivo Pad 上实测通过**，实测数据见 §7。B / C / D 未做，保留为后续选项。

---

## 0. 结论先行

| 结论 | 说明 |
| --- | --- |
| **瓶颈不在解析，在选择** | 解析一话 60MB 的 CBZ 约 1–3 秒，可以接受；真正的痛点是 SAF 选择器只能在一个目录里逐个长按勾选，300 话等于 300 次点击 |
| **零改代码做不到批量** | 现有 APK 没有「按目录导入」入口，Android 也没有「选文件夹后自动逐个喂给某个 App」的机制，必须加一条新入口 |
| **主推方案（已实现）** | `ACTION_OPEN_DOCUMENT_TREE` 选整个文件夹 → 原生递归枚举 → 逐个直写应用私有目录（不经过缓存、不经过 JS 内存） |
| **极速方案（备选）** | `adb push` 整个目录 + App 内「扫描书库目录」，零二次拷贝，300 话约 2–4 分钟 |
| **必须的前置** | 一话一个 `.cbz`，命名形如 `书名 第001话.cbz`。散图目录先用 `tools/pack-manga.mjs` 打包 |

## 1. 改造前的现状：三层瓶颈拆解

> 这一节记录的是**改造前**的代码状况，作为方案依据保留。已修掉的条目在括号里注明现在的行为。

### 1.1 选择层（真正的瓶颈）

`BookPickerPlugin.pick()`（`android/.../BookPickerPlugin.java` L37–53）用的是 `ACTION_OPEN_DOCUMENT` + `EXTRA_ALLOW_MULTIPLE`。这依赖系统 DocumentsUI 的多选能力：

- 只能在**同一目录**内多选，跨目录要退出重进；
- 没有「全选」，滚动 + 逐个点击，300 话 ≈ 300 次点击 + 十余次翻页；
- 部分厂商（含 vivo）自带文件选择器对多选支持更差，表现为「一次只能选一个」。

**这层不改，后面两层优化都没有意义。**

### 1.2 传输层（白白多一份磁盘占用）

选中的每个文件先被**整份复制**到 `cacheDir/picked/`（`BookPickerPlugin` L78–105），再由 JS `fetch(convertFileSrc(...))` 读成 Blob（`js/native.js` L96–108）。代价：

- 同一份内容在设备上存在**两份**（cache + books）；300 × 60MB = 18GB → 峰值需要 36GB；
- `cacheDir/picked/` 里的副本**从来没有被删除过**（全仓库搜索无清理逻辑）——现已改为：下次选文件前自动清，设置页也可手动清；目录导入根本不产生这份副本；
- 整个文件进 JS 堆（Blob + `JSZip.loadAsync` 再解一遍），单文件 200MB 以上极易触发 WebView OOM。

### 1.3 入库层（串行、全量、不可中断）

`js/main.js` `importFiles()`：

| 阶段 | 位置 | 问题 |
| --- | --- | --- |
| 解析 | L104–116 | 串行 `await parsePart()`；**全部解析完才开始写库**，第 250 个文件失败时前 249 个一个也没落盘 |
| 分组 | L118–131 | 一次性把几百个 part 的 cover（dataURL）全留在内存 |
| 写盘 | L156–159 / L195–198 | `db.putFile` → 4MB 分块 + base64（`files-native.js` L36–48），体积膨胀 33%，CPU 全在字符串上 |
| 无进度细化 / 无取消 | — | 面板只有「解析中/已导入」，没法中止 → 现已分批入库、可停止 |

### 1.4 三个硬上限（批量导入会撞到）

| 上限 | 位置 | 后果 |
| --- | --- | --- |
| 书架 500 本 → 已放宽到 5000 | `import.js` L9 `MAX_BOOKS` | 命名不带系列名时，300 话就是 300 本 |
| 单文件 400MB | `import.js` L10 | 超过直接报错 |
| 单本 200 分段 → 已放宽到 2000 | `main.js` L249 `bookParts(b).length < 200` | **一次性**导入超过上限也不受限；但**分批追加**越过上限时会找不到系列，另建一本同名书 |

### 1.5 去重键太粗

`partKey = name|size`（`parts.js` L123）。同名同大小、内容不同的文件会被判为「已在书中」而跳过；反过来，同一话换了文件名就会重复入库。

**粗算**：300 话 × 60MB。当前链路 = 磁盘 36GB 峰值 + 约 10–15 分钟解析 + 写盘时间，且中间不能碰屏幕。

## 2. 四套可行方案对比

| | A. 目录导入<br>（SAF Tree） | B. adb 直推 + 扫描 | C. 合集包<br>（bundle.zip） | D. 局域网 HTTP 上传 |
| --- | --- | --- | --- | --- |
| 一次可导入 | 不限（实测建议 ≤2000 文件） | 不限 | 一个包内不限 | 不限 |
| 速度 | 磁盘拷贝级，20–60MB/s | 同左，且零二次拷贝 | 需解开一层再逐个解，最慢 | 受 Wi-Fi 限制，约 10–30MB/s |
| 操作步数 | 选 1 次文件夹 | 命令行 1 条 + App 点 1 次 | 选 1 个包 | 浏览器拖 1 次文件夹 |
| 改动量 | 原生 ~250 行 + JS ~200 行 | 中（扫描 + 索引重建） | 中（流式解压） | 大（内嵌 HTTP 服务 + 上传页） |
| 前置条件 | 文件已在平板存储里 | USB 调试 + adb + 可调试包 | 需先在 PC 打包 | 同一 Wi-Fi |
| 适用场景 | **日常主力** | 一次性灌库、开发调试 | 网盘传输、备份归档 | 无线、反复增量 |
| 主要风险 | DocumentFile 枚举慢；授权失效 | 普通用户门槛高；Android 11+ 目录受限 | 磁盘占用翻倍；单包过大易失败 | 需处理权限、唤醒、配对 |

补充一个**小批量**方案：`ACTION_SEND_MULTIPLE`（从文件管理器多选后「分享到一册」）。改动约 60 行，但同样受「多选靠手点」限制，只能解决 20–30 话的场景，列为可选。

### 推荐组合

```
        文件在 PC ──┬─ USB/MTP 拷到平板 ──→ 【方案 A 目录导入】   ← 日常
                    ├─ 平板直插 U 盘/读卡器 ─→ 【方案 A 目录导入】   ← 最省事
                    └─ adb push ───────────→ 【方案 B 直推扫描】   ← 300+ 话灌库最快
```

**先做 A，再补 B**；C 作为「文件要先过一遍网盘」时的过渡；D 留到有增量更新需求再做。

## 3. 前置条件与格式要求

### 3.1 容器格式（`import.js` `detectType` / `comicEntries` 决定）

| 扩展名 | 是否支持 | 说明 |
| --- | --- | --- |
| `.cbz` / `.zip` | ✅ | 按漫画处理，读包内图片 |
| `.cbr` / `.rar` | ❌ | JSZip 只认 ZIP，**必须先转 CBZ**（`pack-manga.mjs` 会点名报错） |
| `.epub` | ✅ | 按小说处理，读 spine |
| `.txt` / `.md` | ✅ | ≤20MB，按「第X章」切分 |
| `.pdf` | ✅ | 交给 WebView 内置查看器，**不记页码** |

ZIP 内部要求：

- 压缩方式 store 或 deflate 均可；**不能加密**，不能用 zip64（单包 >4GB）；
- 文件名编码 UTF-8 最佳（GBK 文件名会乱码，但不影响打开）；
- 会被自动忽略：`__MACOSX/`、隐藏文件、`thumbs/`、`thumbnail/` 目录（`comicEntries` L33–45）。

### 3.2 图片格式

`jpg/jpeg/png/webp/gif/bmp/avif`。单页建议宽度 1200–1800px、JPEG 质量 80–85，一话控制在 30–80MB —— 超过 400MB 会直接拒收。

### 3.3 命名规则（决定「能否自动并成一本书」）

`parts.js` `seriesInfo()` 从文件名识别卷/话号并剥出书名主干，主干相同即归为同一本。可识别写法：

```
葬送的芙莉莲 第001话.cbz     ← 推荐
葬送的芙莉莲 第12卷.cbz
葬送的芙莉莲 Vol.03.cbz  /  v03
葬送的芙莉莲 ch.045.cbz
葬送的芙莉莲 (12).cbz
葬送的芙莉莲 12.cbz          ← 末尾裸数字
```

要并成一本书，必须满足：**书名主干一致 + 每话带可解析的序号**。已验证：

```
葬送的芙莉莲 第001话.cbz → key: 葬送的芙莉莲 | order: [1]  | grouped: true
葬送的芙莉莲 第002话.cbz → key: 葬送的芙莉莲 | order: [2]  | grouped: true
葬送的芙莉莲 第010话.cbz → key: 葬送的芙莉莲 | order: [10] | grouped: true
```

注意：4 位年份（1900–2099）不会被当成卷号；`第01话 序章` 这类还能靠主干兜住，但主干里若混进「序章/番外」等不同词，会裂成两本书（导入后可用「多选合并」补）。

### 3.4 目录结构

层级不限（递归扫描）。**选择文件夹 = 直接导入整书**：所选目录合并为一本书，书名用文件夹名，封面固定用第一话；同一目录重复导入会并入旧书不重复建。

```
manga/                          ← 平板上的根目录，方案 A 选它
└─ 葬送的芙莉莲/
   ├─ 葬送的芙莉莲 第001话.cbz
   ├─ 葬送的芙莉莲 第002话.cbz
   └─ …
```

> 想一次导多本时，选上一层目录会把多个系列合成一本；此时应逐个系列文件夹导入。
> 散图目录（未打包）**不能直接导入**，必须先打包（见 §4.1）。

### 3.5 数量与空间

| 项 | 当前上限 | 批量前建议 |
| --- | --- | --- |
| 书架本数 | 500 本 | 系列命名 → 300 话只占 1 本 |
| 单本分段 | 200（仅影响分批追加） | 超过 200 话分两批导入后用「多选合并」 |
| 单文件 | 400MB | 一话一文件，别把整部打成一个 cbz（会丢分章） |
| 空间余量 | 私有目录 | **≥ 总量 × 2**（改造后 × 1.1） |

## 4. 操作步骤

### 4.1 步骤 0：PC 端把 manga 整理成 App 能吃的形状（所有方案都要做）

新增工具 `tools/pack-manga.mjs`（无第三方依赖，Node 18+）：

```bash
# 先体检，不写文件
node tools/pack-manga.mjs "D:/manga/葬送的芙莉莲" --dry-run

# 正式打包：每个图片目录 → 一个 CBZ，按话号补齐命名
node tools/pack-manga.mjs "D:/manga/葬送的芙莉莲" --book "葬送的芙莉莲"

# 已有 cbz 的目录：原样搬运 + 可选每 50 话打一个传输包
node tools/pack-manga.mjs "D:/manga/海贼王" --bundle 50
```

它会做四件事：

1. 递归找「直接含图片的目录」= 一话，图片按自然序重命名为 `001.jpg`、`002.jpg`…（`p10` 排在 `p2` 之后）；
2. 输出 `书名 第001话.cbz`（store 方式打包，不二次压缩图片）；
3. 已有 cbz/epub/txt/pdf 原样复制，cbr/rar 点名报错；
4. 体检并提示：超过 200 话、单文件超 400MB、空目录、RAR。

输出默认在 `manga/../yice-import/`，只放整理结果，不动原目录。

### 4.2 路径 A：目录导入（已实现）

1. PC 上把 `yice-import/` 整个目录拷到平板：`内部存储/Download/manga/`（USB MTP 或 U 盘 OTG 都行）。
2. 打开一册 → 右上角「导入」→ 弹窗里选 **「选择文件夹」**（选「选择文件」等于原来的单/多选）。
3. 系统目录选择器直接落在 `Download` → 点进 `manga` → 底部「使用此文件夹」→ 系统问「要允许一册访问 manga 中的文件吗？」→ 允许。
4. App 弹出确认：「发现 312 个文件，约 18.4 GB。文件会复制到应用内，原目录保持不动。」→ 开始导入。
5. 右下角进度面板：「87 / 312 · 第088话」，每行右侧是「写入中 / 已归入本书 / 已在书中 / 失败」；标题栏有 **停止**。
6. 完成后 toast：「已导入 312 个文件，新增 1 本」，书架出现「书名 · 312 章」。

### 4.3 路径 B：adb 直推（300 话以上最快）

```bash
# 1. 平板开启「开发者选项 → USB 调试」，插线，确认授权
adb devices

# 2. 直接推整个目录到 App 外置私有目录（不进系统相册，不触发媒体扫描）
adb push "D:/manga/yice-import" /sdcard/Android/data/cc.tomereader.yice/files/books/

# 3. App 内：设置 → 书库 → 「扫描书库目录」
```

前提：改造时把书库根目录从 `getFilesDir()`（`/data/data/...`，adb 进不去）换到 `getExternalFilesDir(null)`（`/sdcard/Android/data/...`，adb 可写），并新增「扫描目录 → 重建索引」入口。若不想改存储根，就退回路径 A（把目录放公共存储，用「导入文件夹」指向它）。

### 4.4 路径 C：合集包（要过网盘时）

```bash
node tools/pack-manga.mjs "D:/manga/海贼王" --bundle 50
# → 海贼王-打包01-50话.zip … 每个约 3GB
```

App 端需要新增「导入合集包」：流式解出一层，再逐个走现有 CBZ 管线。磁盘要能同时容纳压缩包与解出的内容。

### 4.5 导入后核对（每次批量都做）

- [ ] 书架本数 = 预期（系列合并后应为「系列数」，不是话数）
- [ ] 点开一本 → 目录里章节数 = 话数，顺序从第 1 话往后递增
- [ ] 随机抽 3 话打开：封面正常、页数正常、翻页正常
- [ ] 设置页「存储占用」≈ 文件总量（明显偏大说明缓存副本没清）
- [ ] 强杀 App 重进，进度与书目还在

## 5. 注意事项

### 会直接失败

1. **CBR/RAR 一律不支持**，先转 CBZ（脚本会列出）。
2. **单个文件 >400MB** 直接报错；整部漫画打成一个 cbz 虽然能导入，但会**丢掉分章**（`reader-comic` 的 `getToc` 按「分段」分组，一个文件 = 一个分段 = 一组）。
3. **ZIP 带密码 / zip64** 打不开。
4. 导入中**锁屏或切后台**：WebView 被冻结，长任务会中断（改造成分批入库后，中断只影响当前一批）。

### 会浪费时间或空间

5. **缓存副本**：走「选择文件」仍会在 `cacheDir/picked/` 留一份副本（下次选文件前自动清，也可在 设置 → 数据 →「清理缓存」手动清）。**目录导入不产生这份副本**，占用只有 1×。
6. 几百个文件连续解析 10 分钟以上，**插上充电器**，别在低电量模式跑。
7. **MTP 拷几百个小文件极慢**（每个文件一次握手），优先 U 盘 OTG 或 `adb push` 整个目录。
8. 单本分段上限已放宽到 **2000 话**；超过会被当成另一本书，需用「多选合并」并回去。

### 容易踩的坑

9. **中文文件名过 adb**：Git Bash 下 `adb push` 可能截断/乱码（此前 `夜航.cbz` 被截成 `夜航.`）。用 Windows `cmd`/PowerShell 执行，或把目录名先改 ASCII。
10. **同名同大小去重**：改过内容但没改文件名和体积的文件会被判「已在书中」跳过（现在会在复制前就跳过，不浪费空间）。需要重导就改名或加 `_v2`。
11. **SAF 授权会失效**：源目录被移动/删除/重命名后，持久授权指向的 URI 就失效，需要重新选目录。
12. **卸载即清空**：书库在应用私有目录，卸载 App 会删掉全部导入内容（源文件还在 PC 上，但平板上的要重来）。
13. **PDF 不记页码**，批量导入 PDF 前先确认能接受。
14. 部分机型首次打开超大目录（几千文件）时，系统目录选择器本身会卡十几秒，属正常。
15. 选目录后到弹出确认框之间是**原生枚举**（每个目录一次 ContentResolver 查询），300 个文件约 1–3 秒，界面无进度提示属正常。
16. 300 章的书第一次打开需要约 2–4 秒建页表（要把 300 个分段的页数拼起来），之后翻页不再等待。

| 场景 | 结果 |
