# 平板端实现说明：从 Web 版到可安装的平板 App

> 对应 `docs/02-Android平板改造方案.md` 的第 1–5 阶段。
> 桌面浏览器里打开仍然是同一套界面，宽度够就自动切到平板布局。

## 1. 目标与范围

**目标**：同一份前端代码，既能在浏览器里跑，也能装成安卓平板 App；阅读引擎、书架、多选合并等既有功能一行不删。

**这一轮做了什么**

| 阶段 | 内容 | 状态 |
| --- | --- | --- |
| 1 | Capacitor 起壳，`webDir` 指向构建产物 | ✅ |
| 2 | 文件存储抽象：浏览器 IndexedDB / 原生私有目录 | ✅ |
| 3 | SAF 文件选择插件，替换 `input[type=file]` | ✅（待真机编译验证） |
| 4 | 返回键、手势翻页、安全区、常亮、状态栏 | ✅ |
| 5 | 平板默认值（横屏双页、竖屏窄版心）、横竖屏回归 | ✅ |
| 6 | 性能兜底（模糊降级、旧内核兜底） | ✅ 部分 |
| 7 | 签名打包、真机回归 | ⏳ 需 Android Studio |

**不在这一轮**：iOS 工程、书库云端同步、PDF 原生渲染。

## 4. 关键交互

### 4.1 触屏轻扫翻页（`js/reader.js`）

- 阈值：横向 ≥56px，纵向 ≤40px 或明显不是横向手势；超过 900ms 不算轻扫。
- **边缘避让**：屏幕左右 24px（叠加安全区）内起手直接放弃，留给系统返回手势。
- 漫画 RTL 时方向对调；条漫模式、放大状态、面板打开时不响应。
- 翻页后 420ms 内忽略补发的 `click`，避免"扫一下翻两页"。
- 可在「设置 → 平板 → 手势翻页」关掉。

### 4.2 系统返回（`js/main.js` + `js/native.js`）

按钮/手势的消费顺序，返回 `true` 表示 App 吃掉这次返回：

```
阅读器面板打开 → 关面板
阅读器打开     → 退出阅读器（先落盘）
有对话框打开   → 关对话框
右键菜单打开   → 关菜单
处于多选       → 退出多选
以上都没有     → 交给系统（退出/最小化 App）
```

安卓端走 `@capacitor/app` 的 `backButton`；浏览器里监听 `native-back` 自定义事件，方便调试与自动化。

### 4.3 安全区

两层来源取较大值：

1. CSS `env(safe-area-inset-*)`；
2. `MainActivity` 实测 `WindowInsets`，除以密度后通过 `window.__setNativeInsets()` 推给 JS。

为什么两套都要：WebView 在部分机型上 `env()` 返回 0（尤其非全屏时），而原生 inset 稳定；反过来纯浏览器里又没有原生注入。JS 把结果写到 `--safe-top/right/bottom/left`，样式统一用这四个变量。

### 4.4 平板默认值（只影响"第一次打开"的书）

- 横屏首次打开漫画 → 双页对开；
- 竖屏首次打开文字书 → 版心「窄」（不再贴着边缘）；
- 用户在任何一本书里改过设置，就按单本保存，不再套默认值。

### 4.5 性能兜底

`platform.js` 按 `deviceMemory` / `hardwareConcurrency` 打上 `data-perf="low"`，此时阅读器工具条与抽屉去掉 `backdrop-filter`，改用不透明底。`@supports not (color-mix(...))` 给旧内核兜住关键颜色。

## 5. 存储与导入

| 能力 | 浏览器 | 原生壳 |
| --- | --- | --- |
| 书籍元数据 / 进度 / 偏好 | IndexedDB | 同左 |
| 原始文件 | IndexedDB Blob | `Directory.Data/books/*`，IndexedDB 只存 `{id,name,type,size,path}` |
| 写入 | `tx('files').put({file})` | 4MB 分块 `Filesystem.writeFile/appendFile` |
| 读取 | 直接取 Blob | `getUri` → `convertFileSrc` → `fetch` → `File` |
| 占用统计 | `navigator.storage.estimate()` | 索引里累加 `size` |
| 选文件 | `<input type=file>` | `BookPicker.pick()`（SAF） |

`js/db.js` 的对外接口没有变化（`putFile/getFile/deleteFile/clearAll/usage`），所以导入、合并、删除、清空这些业务代码一行没改。

SAF 插件返回：

```json
{ "files": [ { "name": "夜航 01.cbz", "path": "/data/user/0/.../cache/picked/1731-夜航 01.cbz", "size": 117201, "type": "application/vnd.comicbook+zip" } ] }
```

JS 侧把 `path` 包成 `File` 后直接进原有解析管线。

### 5.1 批量导入（v1.1 新增）

单文件选择器在「几百话」场景下不可用（只能在一个目录里逐个长按），因此加了一条独立通路，设计与实测见 `docs/04-批量导入方案.md`：

| 步骤 | 实现 |
| --- | --- |
| 选目录 | `BookPicker.pickFolder()` → `ACTION_OPEN_DOCUMENT_TREE`，带 `EXTRA_INITIAL_URI` 直接落在 `Download`，`takePersistableUriPermission` |
| 枚举 | 原生 `DocumentsContract.buildChildDocumentsUriUsingTree` 递归（每目录一次查询），跳过隐藏/`__MACOSX`，上限 5000，每 25 个文件推 `enumProgress` |
| 落盘 | `BookPicker.stage({uri,id,name})` 用 256KB 缓冲直写 `files/books/<id>.<ext>`，**不经过 cacheDir**，也不进 JS 堆 |
| 页数 / 封面 | 落盘后 `ZipFile` 读中央目录数图片条目，抽第一张图到 `cache/covers/<id>`，JS 只 `fetch` 那张小图 |
| 入库 | `files.adopt(id, meta)` 只写索引；`commitItems()` 每 20 个一批分组写库，进度面板可「停止」 |
| 收尾 | `clearCovers()` + `files.sweep()` 清掉封面临时文件与中断残片 |

因此 `db.js` 新增了两个方法：`adoptFile()`（登记已存在的文件）与 `sweepFiles()`（清孤儿文件），其余接口不变。

### 7.3 真机暴露并修掉的一个 bug

**点击屏幕呼不出工具栏**。安卓 WebView 里点一下会先补发一个合成的 `mousemove`，再派发 `click`：

1. 合成 `mousemove` → `onMove()` → `wake()` 把 `idle` 摘掉；
2. 紧接着 `click` → `onStageClick()` 用 `classList.contains('idle')` 判断，此时已经不是 idle，于是走 `toggleChrome()` 的 else 分支，**又把工具条藏回去**。

表现就是按一下只闪一下，永远唤不出来——这条路径在浏览器里用鼠标点很正常，只有真机触摸才复现。

修法（`js/reader.js`）：

- `onMove` 忽略 `e.sourceCapabilities.firesTouchEvents` 的合成 mousemove；
- 工具条状态改用模块变量 `chromeHidden`，不再从 DOM class 反推，`wake()` / `hideChrome()` / `toggleChrome()` / `setPanel()` / `closeReader()` 统一维护它。

`verify8.py` 增加 4 项复现用例（派发带 `firesTouchEvents: true` 的 mousemove 再 click）。把修复临时回退后这 4 项会 FAIL，恢复后 PASS，确认测试能抓住这个回归。

   打包侧的静态核对：

   | 检查项 | 结果 |
   | --- | --- |
   | `aapt2 dump badging` | `cc.tomereader.yice`，`versionCode 3` / `versionName 1.1`，`minSdk 26`，`targetSdk 34`，label `一册` |
   | launchable-activity | `cc.tomereader.yice.MainActivity` |
   | manifest | `largeHeap=true`、`screenOrientation=13`(fullUser)、`configChanges=0x1ff4`、theme 已替换 |
   | dex | `classes10.dex` 内有 `MainActivity` 与 `BookPickerPlugin`，`classes9.dex` 有 `R` |
   | assets | `assets/public/` 26 个文件，含 `index.html`、`css/tablet.css`、`js/platform.js`、`js/native.js`、`js/storage/*` |
   | 签名 | `apksigner verify` 通过，`CN=Android Debug` |

2. `targetSdk` 保持 34；升 35 要连带升 AGP，属于打包阶段的事。
3. **数据不互通**：浏览器的 IndexedDB 与 App 私有目录是两套存储，装 App 后需要重新导入一次书。若要做迁移，可在首次启动时提供「从本地备份 zip 导入」。
4. 「选择文件」仍会复制一份到 `cacheDir/picked`（下次选文件前自动清，也可在设置里手动清）；**目录导入不产生这份拷贝**，长期保存的是 `Directory.Data/books`。
5. 大文件（>200MB 单本）的分块写入未在真机压测，若出现 OOM 可把 `CHUNK` 从 4MB 降到 1MB（`js/storage/files-native.js`）。
6. 手势翻页只做左右轻扫，没有做"拖动跟手翻页"的动画；需要的话在 `reader.js` 里给 `.reader-stage` 加 transform 即可，但会影响 EPUB 的分栏测量，建议单独开一个 `swipe-preview` 图层。
7. **批量导入只在 Android 壳里可用**：浏览器没有目录选择入口，仍是单/多选文件。方案 B（adb 直推 + 扫描）与 C/D（合集包、局域网）未做，需要时按 `docs/04` 的顺序补。
8. 300 章以上的书第一次打开要 2–4 秒建页表；要更快可以把页数缓存进书籍记录（导入时已有 `count`，目前只在打开时现拼）。
